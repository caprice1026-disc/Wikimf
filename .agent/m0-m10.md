## Surprises & Discoveries

開始時点の Docker daemon は停止していたため、公式Windows PostgreSQL17.6を `.tooling/` に隔離して起動した。55439はWindows予約ポートでbind拒否、54329で成功。Pythonのlocalhost接続がDNS解決で停止したため、DBは127.0.0.1を使用する。PG外部キーでsession INSERT前のevent INSERTが拒否され、明示flushを追加した。PGの27テストが通り、16並列再送と削除競合も確認した。

Android SDK/JDK/adb は開始時不在だったが隔離ツール導入とAPI35エミュレータ起動が成功した。Google/GitHub登録設定・HTTPS配備先・実機は未準備とユーザーが回答し、エミュレータ代替と未実施項目のST引継ぎを明示した。これらは実機/OAuth実認証passには置き換えない。

## Plan of Work

M0 で Python 依存と migration、契約 schema、docker compose と再現可能なコマンドを用意する。固定 fixture は外部 API に依存させない。M1〜M4 の実装は分担し、API 形を契約ファイルへ固定して一致させる。OAuth 実設定がない場合も fake provider はテスト専用に限定し、本番 API には偽ログインを露出しない。

M5〜M8 は先にイベント・session の不変条件と重複制約を固定する。各イベントに区間と snapshot を含め、欠落分を累積値で補完しない。同一利用者の時間を受理順に割り当てることで複数端末の重複を除き、session 判定にも割当後時間を使う。順序逆転は許可し、seq 順の矛盾は session 全体を隔離する。記事別最大推定文字数の増分は観測日時へ帰属させ、日跨ぎは指定 timezone で区間を分割する。

M9 では Web session+CSRF だけが管理操作できる。記事削除は raw event、session、手動設定を消し cutoff を保存する。全消去は epoch を更新する。アカウント削除は全認証情報を無効化する。公開 API は許可された総時間・称号のみ返し、個人応答と共有しない。

M10 では PostgreSQL 実行、並行送信と削除 race、migration の適用/rollback、backup と削除台帳適用復元、Dashboard と実 Chrome の確認、Android APK のビルドと可能なら実機確認を行う。配布物は version/schema/policy/commit を対応付ける。70ケースの受入台帳に実行と未実行の理由を残す。

## Validation and Acceptance

health は HTTP200。許可外URLと曖昧な識別子は拒否する。初期ユーザーのプロフィールは匿名で取得できない。端末連携 secret なしでは交換できず、二回目交換は拒否する。同じ event を10回送っても計上は一回、内容違いは conflict。60秒の異なる端末区間が30秒重なると合計90秒。削除前 session と旧 epoch の再送は拒否。manual state は時間と文字数を変えない。projection の再構築は同じ値になる。これらは SQLite だけでなく PostgreSQL で確認する。実機・実 OAuth 未実施の場合、その M10 gate は未完と記録する。

## Idempotence and Recovery

既存ファイルは保持し、追加ファイルを中心に実装する。migration は Alembic revision 管理、DB volume は削除しない。backup 復元前にサービスを停止し、最新の削除/失効台帳を別保管して古い backup へ再適用する。復元時は Web session と端末 token を全失効し再連携する。token・秘密値はログや配布 manifest に残さない。
