# Chrome MV3 client

Build from the repository root with `node apps/extension/build.js`. Set `WIKIMF_API_ORIGIN` to the HTTPS backend origin and `WIKIMF_DASHBOARD_ORIGIN` to the trusted Dashboard origin for distribution; HTTPS deployments default Dashboard to the API origin. Development defaults are `http://localhost:8000` and `http://localhost:5173`. Load `apps/extension/dist` as an unpacked extension in `chrome://extensions` with Developer mode enabled. Chrome 114 or newer is required. Rebuild and use Reload after source changes; tokens and the durable queue stay under the same unpacked path/extension identity. Removing the extension deletes its local records; revoke its device in Dashboard before uninstalling.

Open the popup and link the account. The worker obtains a one-time device link, opens the backend's verification page, and exchanges its secret after the user approves in their regular browser session. The secret/token never appears in Wikipedia pages or the popup response. Cloud collection consent must also be enabled in Dashboard. Recording starts only after enabling the popup checkbox.

Only Japanese/English current articles in the focused window's active tab are eligible. The popup shows recording, sync, queued/rejected/lost counts, pause controls, retry, discard, unlink, and the Dashboard link. Local pause can retain queued observations without sending or continue their synchronization, according to the checkbox. Unlinking can synchronize first or explicitly discard unsent records. Incognito is disabled. Article eligibility comes from the backend; anchor changes keep the current Document.

The worker restricts `storage.local` and `storage.session` to `TRUSTED_CONTEXTS`; Chrome does not encrypt local storage. Credentials, settings, and the owner/device-bound outbox have separate keys. An immutable event is saved before network delivery. Only its item ACK removes it; terminal rejection retains bounded diagnostic metadata. Authentication errors stop new measurement. Epoch/deletion controls prune stale records before upload and count losses. The queue budget is 8 MiB to leave space under Chrome's 10 MiB storage quota; the age limit is seven days. Filling the queue stops new cloud measurement instead of replacing old records. After discard, control cleanup, or ACK, recording resumes when no expired row remains and there is room for one maximum-sized observation. Authentication, owner, device, and schema failures stay stopped until the user completes a new device link. The popup shows these stops as paused while preserving the recording checkbox.

Permissions are `storage`, `alarms`, the two Wikipedia hosts, and the configured backend origin. No history/cookies/all-sites permission, arbitrary proxy-fetch messaging, external messaging, or remote executable code is included.

Run `npm.cmd test --prefix apps/extension` for queue, recovery state, and trust-boundary tests. `node apps/extension/test/chrome-smoke.js` launches the installed Google Chrome in a new repository-local test profile, loads the unpacked client using official DevTools `Extensions.loadUnpacked`, and verifies actual DOM, content isolation, popup, tab arbitration, offline storage, service-worker stop/restart, and ACK. `node apps/extension/test/queue-recovery.chrome.js` checks full/expired queue recovery, terminal failure retention, popup/lease agreement, and worker restarts. Their APIs are explicit local fixtures; they do not claim production OAuth verification. Set `WIKIMF_CHROME` and `WIKIMF_NODE_MODULES` for other installations. Test extension builds, reports, screenshots, and profiles stay under the ignored `.browser-tests/` directory.

The distribution folder is an unpacked verification artifact. It has not been submitted to the Chrome Web Store. This is an independent unofficial service, and Wikipedia content stays rendered by Wikipedia.

`node test/backend-chrome.js` (from this package) connects to the repository's separately started PostgreSQL/FastAPI QA server using `.tmp/backend-smoke.json`. It proves strict real API ACK and database activity/stat projections for actual tracker events. Its identity and article metadata remain synthetic, and it never prints credential values. This command requires the local QA server and is intentionally separate from offline CI.
