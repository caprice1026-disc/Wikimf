The historical Issue #15 / #17 passing count was eight: four privacy tests, two persistence tests, one explicit live-page focus test and one explicit management Intent test. All eight ran together on that APK, with real Wikipedia activity accepted above 10,000 ms by the restarted API/PG service. The current eleven-case suite above supersedes that count. The ordinary instrumentation run skips external-service tests unless explicitly enabled; skipped cases are not included in passing counts. Gradle's UTP result collector failed in this restricted Windows host; actual AndroidJUnitRunner results were obtained directly through adb.

Database version 2 preserves the active queue and local article history, replaces terminal quarantine rows with safe diagnostics containing only event ID, owner, code and timestamp, and limits diagnostics to the latest 100 across the device. SQLite secure deletion is enabled. The migration regression checks both logical rows and absence of the erased marker from the actual database file. Diagnostic counts represent retained bounded entries, not a lifetime total. The first implementation's `execSQL` use for the result-returning PRAGMA was rejected on the emulator; `rawQuery` corrected it, and that failed attempt is excluded from passing counts.

Both background sync and Reader use the same fresh recording control and local cleanup. The shared HTTP guard rechecks consent, collection and device binding before each reading-content request. Control errors suppress Reader URL resolution while Wikipedia remains available. OFF-state UI explains local retention and offers discard before reconsent. The HTTP regressions exercise the actual Android OkHttp/SQLite/Keystore path against a synthetic emulator loopback server, using isolated storage; they do not exercise production OAuth or HTTPS.

The Keystore persistence test uses a separate device-protected storage realm and verifies that setting the same API URL or a trailing-slash variant preserves credentials and consent. Changing the destination clears both before publishing the new URL, preserves the old owner/device queue, and rejects an already captured old credential before any HTTP request. The actual linked test account remains in credential-protected storage and was preserved.

The three search cooldown regressions cover Retry-After seconds, HTTP-date, past dates, invalid-value fallback and overflow; independent wiki deadlines, extension and expiration; and cancellation of an earlier query while the latest generation waits for the retained deadline. An actual injected HTTP 429 UI scenario remains ST-06.

Real Compose button clicks produced `http://10.0.2.2:5173/app` and `http://10.0.2.2:5173/app/settings/privacy`. A separate physical click launched Chrome with the privacy URL. Chrome remained on its first-run screen, without terms acceptance or sign-in; completed browser login/navigation remains ST. Initial automation attempts could not search Compose virtual nodes or scroll its lazy list; native-tree traversal and a touch swipe corrected the test harness. Failed attempts are not passing tests.
